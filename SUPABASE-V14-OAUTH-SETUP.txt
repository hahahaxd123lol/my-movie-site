============================================================
5. HOW V14 HANDLES FIRST-TIME SOCIAL USERS
============================================================

When Google/Discord authentication succeeds:

1. Supabase Auth signs the user in.
2. If they do not yet have public.profiles row:
   ensure_my_oauth_profile() creates one.
3. Username is converted to strict ASCII letters/numbers.
4. If the requested username already belongs to somebody, V14 generates a
   unique variant tied to the user's UUID.
5. Auth metadata username/chat_alias is synchronized.
6. The account remains a normal Member.
7. Warnings/bans/Staff permissions remain UUID-backed as before.

Google/Discord login does NOT automatically grant Staff.

============================================================
7. PLAYER SANDBOX CHANGE
============================================================

V14 removes the HTML sandbox attribute from the streaming iframe because some
providers refuse to run inside sandboxed frames.

V14 adds best-effort parent-page protections:
- blocks external window.open calls made by Flix2Watch parent-page code
- detects recent provider-frame interaction
- requests browser confirmation on suspicious immediate top-page navigation
- refocuses the Flix2Watch window after provider-frame blur

IMPORTANT:
Once a cross-origin iframe is unsandboxed, browser Same-Origin Policy means
Flix2Watch cannot guarantee blocking every popup created by the provider itself.
There is no parent-page JavaScript replacement that has sandbox-equivalent
control over arbitrary code running on another origin.
